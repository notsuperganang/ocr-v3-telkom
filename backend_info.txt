=== 4. API ENDPOINTS ===

--- Authentication (prefix: /auth) ---

POST /auth/login
  Description: Authenticate user with username/password, return JWT token plus role and user_id.
  Request body: { "username": str, "password": str }
  Response: { "access_token": str, "token_type": "bearer", "username": str, "role": str, "user_id": int }

POST /auth/logout
  Description: Client-side logout (no server-side token invalidation).
  Response: { "message": "Successfully logged out" }

GET /auth/me
  Description: Return current authenticated user's profile.
  Auth: Bearer token required.
  Response: { "user_id": int, "username": str, "email": str, "full_name": str|null, "role": str, "is_active": bool, "authenticated": bool }

PATCH /auth/update-profile
  Description: Self-service profile update for authenticated users (email and/or full_name).
  Auth: Bearer token required.
  Request body: { "email": str|null, "full_name": str|null }
  Response: { "message": str, "user": UserInfo }

=== 5. AUTHENTICATION & RBAC ===

Mechanism: JWT (JSON Web Tokens) via python-jose library. Passwords hashed with bcrypt via passlib.

Token Generation (app/auth/utils.py):
  create_access_token(data: dict, expires_delta: Optional[timedelta]) -> str
    Encodes payload with HS256 algorithm using jwt_secret_key from settings.
    Default expiry: jwt_access_token_expire_hours (default 24 hours) from settings.

  create_auth_token(user: User) -> str
    Builds token payload: {"sub": str(user.id), "username": user.username, "role": user.role.value, "iat": datetime.utcnow()}
    Calls create_access_token() internally.

  verify_token(token: str) -> Optional[dict]
    Decodes and verifies JWT. Returns payload dict or None if invalid.

  authenticate_user(db: Session, username: str, password: str) -> Optional[User]
    Queries User by username, checks is_active, verifies bcrypt hash, updates last_login_at on success.

Password Hashing:
  pwd_context = CryptContext(schemes=["bcrypt"], deprecated="auto")
  verify_password(plain_password, hashed_password) -> bool
  get_password_hash(password) -> str

HTTP Transport: Bearer token scheme (fastapi.security.HTTPBearer).

Dependency Injection (app/auth/dependencies.py):
  security = HTTPBearer()  -- extracts Authorization: Bearer <token> header.

  get_current_user(credentials: HTTPAuthorizationCredentials, db: Session) -> User
    1. Extracts credentials.credentials as raw token string.
    2. Calls verify_token(token) -- returns None on failure.
    3. Extracts payload["sub"] as user_id string, converts to int.
    4. Queries User by id.
    5. Raises 401 if user not found; 403 if user.is_active is False.
    6. Returns User ORM object.

  require_manager(current_user: User) -> User
    Depends on get_current_user. Raises 403 if current_user.role != UserRole.MANAGER.

  get_current_user_optional(...) -> Optional[User]
    Same logic but uses HTTPBearer(auto_error=False). Returns None if unauthenticated.

Combined Dependencies (app/api/dependencies.py):
  get_db_and_user(db: Session, current_user: User) -> tuple[Session, User]
    Used by almost all API routes -- provides both database session and authenticated user in one call.

  get_db_and_manager(db: Session, current_user: User) -> tuple[Session, User]
    Same but uses require_manager -- MANAGER-only routes.

Role Enforcement:
  All standard routes (CRUD, contracts, invoices) require any authenticated user via get_db_and_user.
  Admin routes (/api/admin/*) require MANAGER via get_db_and_manager.
  User management writes (POST /api/users, PATCH /api/users/{id}, change-password, deactivate, activate) require MANAGER via get_db_and_manager.
  User management reads (GET /api/users, GET /api/users/{id}) allow any authenticated user via get_db_and_user.
  Self-service profile and password change (PATCH /auth/update-profile, POST /auth/change-password) use get_current_user directly.

CORS: Allowed origins: http://localhost:3000, http://127.0.0.1:3000, http://localhost:5173, http://127.0.0.1:5173. All methods and headers permitted.


=== 6. OCR PIPELINE INTEGRATION ===

File: backend/app/services/ocr_service.py

OCR Library: PaddleOCR PPStructureV3 (paddleocr==3.1.0, paddlepaddle==3.0.0 CPU).
PDF Library: PyMuPDF (fitz) for metadata; pdf2image (convert_from_path via poppler) for page image extraction.

Thread Safety Architecture:
  PaddlePaddle holds per-thread state (mkldnn primitive caches, tensor handles). Calling predict() from
  multiple threads on the same pipeline causes std::exception.
  Solution: A dedicated single-worker ThreadPoolExecutor is created at module import:
    _ocr_executor = ThreadPoolExecutor(max_workers=1, thread_name_prefix="ocr-worker")
  All OCR work must go through run_ocr_async() or the warmup() function -- never asyncio.to_thread()
  or a different executor.

Singleton Pattern:
  _ocr_service_instance: Optional[OCRService] = None
  get_ocr_service() -> OCRService: returns or creates the singleton.
  OCRService.__init__() creates temp directory but does NOT initialize the pipeline (lazy init).
  Pipeline is initialized via _ensure_pipeline() the first time process_pdf() is called, which runs on
  the ocr-worker thread. This guarantees PaddlePaddle state is bound to the single worker thread.

Warmup:
  warmup() submits service._ensure_pipeline to the executor and blocks until done (.result()).
  Called at application startup in main.py lifespan() to avoid paying the ~10s lazy-init cost on the
  first real request.

Pipeline Configuration (from app/config.py / get_pipeline_params()):
  use_table_recognition=True   (required for service count extraction)
  use_seal_recognition=False
  use_formula_recognition=False
  enable_hpi=True              (High Performance Inference, CPU-only; auto-disabled on GPU)
  device="cpu"
  All model names: None (let PPStructureV3 choose defaults automatically)

OCRService.process_pdf(pdf_path: str, output_base_dir: str, file_id: str) -> OCRResult:
  1. Calls _ensure_pipeline() to lazy-initialize if needed.
  2. Creates file_output_dir: {output_base_dir}/{file_id}_ocr_results/
  3. Creates page_temp_dir: {self.temp_dir}/{file_id}/
  4. _convert_pdf_to_images(pdf_path, page_temp_dir): calls convert_from_path(dpi=200, fmt=PNG,
     thread_count=1, first_page=1, last_page=2). Saves page_{i+1}.png files. Processes only first 2 pages.
  5. For each image: _process_page_with_pipeline(image_path, page_num): calls
     self.pipeline.predict(image_path) and returns results list.
  6. _save_page_result(results, page_output_dir, page_num): calls res.save_to_json(save_path=output_dir)
     for each result. Output path: {page_output_dir}/page_{page_num}_res.json.
  7. Returns OCRResult(success=True, file_id=file_id, pages_processed=N, processing_time=T,
     output_paths={"page_1": "path/...", "page_2": "path/..."}).

run_ocr_async(pdf_path: str, output_base_dir: str, file_id: str) -> OCRResult:
  Async wrapper: loop.run_in_executor(_ocr_executor, service.process_pdf, ...).
  Called from process_file_background() background task.

Background Processing Flow (upload.py -- process_file_background):
  1. job.status = PROCESSING; db.commit()
  2. ocr_result = await run_ocr_async(file_path, "storage/ocr_outputs", str(job.file_id))
  3. If success: job.ocr_artifacts = ocr_result.output_paths
  4. Loads page1_path JSON with open(); calls extract_from_page1_one_time(page1_ocr) from data_extractor.py
  5. If page2_path exists: loads page2 JSON; calls merge_with_page2(extracted_data, page2_ocr)
  6. job.extracted_data = json.loads(extracted_data.json())  (uses Pydantic .json() for datetime serialization)
  7. job.status = AWAITING_REVIEW; db.commit()
  8. On error: job.status = FAILED; job.error_message = ...; db.commit()

Data Extraction (app/services/data_extractor.py):
  extract_from_page1_one_time(page1_ocr: dict) -> TelkomContractData
    Processes PP-StructureV3 JSON output from page 1.
    Uses regex patterns and fuzzy matching to extract: customer information (name, NPWP, address,
    representatives), service counts from tables (connectivity_telkom, non_connectivity_telkom, bundling),
    financial data (biaya_instalasi, biaya_langganan_tahunan), payment method (one_time_charge, recurring,
    termin with termin_payments array), contract number.
    Handles OCR text variations and errors with multiple extraction strategies.

  merge_with_page2(page1_data: TelkomContractData, page2_ocr: dict) -> TelkomContractData
    Processes page 2 OCR output to extract: contract duration (jangka_waktu: mulai + akhir dates),
    Telkom contact person (kontak_person_telkom), additional terms.
    Returns merged TelkomContractData.

OCR Output Storage: storage/ocr_outputs/{file_id}_ocr_results/page_{N}_results/page_{N}_res.json


=== 7. KEY BUSINESS LOGIC MODULES ===

--- app/services/denorm.py ---
Purpose: Extract and normalize frequently-queried fields from the final_data JSONB blob into typed Python
values for storage in denormalized contract columns.
Pattern: Stateless functional module. No database access.

Key dataclass:
  DenormFields: Contains all denormalized fields (contract_number, customer_name, customer_npwp,
  period_start/end as date, service counts, payment_method, financial Decimals, all extended fields for
  address/contacts/payment details, recurring computation results, extraction metadata).

Key function:
  compute_denorm_fields(final_data: Dict[str, Any]) -> DenormFields
    Navigates nested dict with _safe_get() to extract each field.
    Calls _parse_decimal(), _parse_date(), _normalize_payment_method(), _parse_timestamp(),
    _normalize_email(), _normalize_phone() for type-safe parsing.
    Calls _compute_termin_summary() for termin count and total amount.
    Calls _compute_recurring_fields() to derive recurring_monthly_amount (annual_subscription_cost / 12),
    recurring_month_count (inclusive months between period dates), and recurring_total_amount.
    Returns safe defaults (None, 0, Decimal('0.00')) on any parsing error -- never raises.


--- app/services/termin_sync.py ---
Purpose: Synchronize the termin_payments array from contract.final_data (JSONB) into
ContractTermPayment database rows. Keeps normalized payment table in sync.
Pattern: Functional, no commit. Called by processing confirm and contract update endpoints.

Key function:
  sync_contract_terms_from_final_data(db: Session, contract: Contract, acting_user: Optional[User] = None) -> None
    If payment method is not "termin" or final_data is missing: deletes all existing term payment rows.
    Otherwise: parses each termin entry (termin_number, period label, amount).
    Calls parse_indonesian_period(period_str) -> (year, month) using Indonesian month name mapping.
    For existing rows: updates amount, period fields, updated_by_id. Preserves status/paid_at/notes/original_amount.
    For new rows: generates invoice_number via generate_invoice_number(db, account_number, year, month),
    calculates due_date, creates ContractTermPayment with status=PENDING and invoice_status=DRAFT.
    Deletes terms no longer in JSON.
    Calls update_termin_statuses() after sync to apply PENDING/DUE/OVERDUE automatically.
    Does NOT commit.


--- app/services/recurring_sync.py ---
Purpose: Generate and maintain monthly billing schedule rows in ContractRecurringPayment from contract
denormalized fields.
Pattern: Functional, no commit. Called by processing confirm and contract update endpoints.

Key functions:
  iter_months_inclusive(start_date: date, end_date: date) -> List[Tuple[int, int, int]]
    Returns list of (year, month, cycle_number) for all months in the contract period.
    Skips partial first month if start_date.day > 1.

  sync_contract_recurring_payments(db: Session, contract: Contract, acting_user: Optional[User] = None) -> None
    Guard clauses: not recurring, no recurring_monthly_amount, no period dates -> deletes all rows.
    Generates expected_months via iter_months_inclusive().
    Matches existing rows by (period_year, period_month).
    Preserves status/paid_at/notes; updates amount, cycle_number, period_label.
    Creates new rows with invoice_number, due_date, status=PENDING.
    Deletes orphaned rows outside the period range.
    Calls update_recurring_statuses() after sync.
    Does NOT commit.


--- app/services/termin_status.py ---
Purpose: Automatically compute and persist PENDING/DUE/OVERDUE status for term and recurring payments
based on current date. Preserves PAID and CANCELLED (manual-only statuses).
Pattern: Functional, no commit. Called by sync functions and by GET endpoints (auto-update before returning data).

Key functions:
  compute_termin_status(period_year: int, period_month: int, current_date: Optional[datetime] = None) -> str
    Compares (period_year, period_month) tuple against (current_year, current_month).
    Returns "PENDING" (future), "DUE" (current month), or "OVERDUE" (past).

  _update_payment_statuses_generic(db, table_model, contract_id, payment_ids, current_date, dry_run, payment_number_field) -> Dict
    Generic internal function works with both ContractTermPayment and ContractRecurringPayment.
    Uses SELECT FOR UPDATE row lock to prevent concurrent race conditions.
    Only updates rows where status is in AUTO_STATUSES (PENDING, DUE, OVERDUE).
    Skips MANUAL_STATUSES (PAID, CANCELLED).
    Only writes if status actually changed (minimize DB writes).
    Returns statistics: checked, updated, skipped_manual, changes list.

  update_termin_statuses(db, contract_id, termin_ids, current_date, dry_run) -> Dict
    Wraps _update_payment_statuses_generic for ContractTermPayment.

  update_recurring_statuses(db, contract_id, recurring_ids, current_date, dry_run) -> Dict
    Wraps _update_payment_statuses_generic for ContractRecurringPayment.


--- app/services/invoice_service.py ---
Purpose: Invoice lifecycle management -- add/edit/delete payments, upload/delete documents,
send/cancel/uncancel invoices. Handles PPh 23 tax validation and database view queries.
Pattern: Functional, no session creation, no commits. API layer (invoices.py) handles commit/rollback.

Key helper functions:
  _get_invoice_model(invoice_type: str) -> Type[...]
    Maps "term" -> ContractTermPayment, "recurring" -> ContractRecurringPayment.

  _get_invoice_type_db_value(invoice_type: str) -> str
    "term" -> "TERM", "recurring" -> "RECURRING" (DB stores uppercase).

  _parse_decimal_amount(value: Any, context: str = "amount") -> Decimal
    Safe decimal parsing with fallback to Decimal('0.00').

  _get_invoice_by_id(db, invoice_type, invoice_id) -> Optional[model instance]

  _validate_payment_amount(invoice, payment_amount: Decimal) -> None
    CRITICAL: Validates against net_payable_amount (not amount). Raises ValueError if payment exceeds
    remaining net payable.

  calculate_due_date(period_year: int, period_month: int) -> datetime
    Returns last day of the billing month at 23:59:59 UTC.

  generate_invoice_number(db, account_number, year, month) -> str
    Calls PostgreSQL function generate_invoice_number() via raw SQL.
    Format: AAAAAAA-NNNNNN-YYYYMM (first 7 chars of account_number, 6-digit cumulative sequence, YYYYMM).

Main service functions:
  get_invoices_by_period(db, year, month, invoice_type, status_list, witel_id, segment_id, customer_name,
  contract_number, page, limit) -> Dict
    Queries v_invoices view with filters. Returns paginated data dict with summary statistics.

  get_invoice_detail(db, invoice_type, invoice_id) -> Optional[Dict]
    Queries v_invoices view for joined data. Loads model with joinedload for transactions and documents.
    Returns dict with invoice, payments, documents, contract keys.

  add_payment(db, invoice_type, invoice_id, payment_data: dict, acting_user: User) -> PaymentTransaction
    Validates payment amount against net_payable_amount.
    Creates PaymentTransaction, updates invoice.paid_amount and tax flags.
    Updates invoice.updated_by_id. Does NOT commit.

  edit_payment(db, payment_id, payment_data: dict, acting_user: User) -> PaymentTransaction
    Reverses old payment amount, validates new amount, updates transaction. Does NOT commit.

  delete_payment(db, payment_id, acting_user: User) -> Dict
    Removes transaction, reduces paid_amount. Does NOT commit.

  upload_document(db, invoice_type, invoice_id, file: UploadFile, document_type, payment_transaction_id,
  notes, acting_user) -> InvoiceDocument
    Async function (awaits file.read()). Validates file type and size (max 10MB).
    Saves to storage/invoices/{invoice_type}/{invoice_id}/{uuid}_{filename}.
    Creates InvoiceDocument record. If BUPOT_PPH23 document uploaded, sets pph23_paid=True.
    Does NOT commit.

  delete_document(db, document_id, acting_user) -> Dict
    Deletes file from filesystem, removes record. If last BUPOT_PPH23, sets pph23_paid=False.
    Does NOT commit.

  send_invoice(db, invoice_type, invoice_id, acting_user) -> None
    Only DRAFT can be sent. Sets invoice_status="SENT", sent_date=now. Does NOT commit.

  cancel_invoice(db, invoice_type, invoice_id, acting_user) -> None
    Cannot cancel PAID invoice. Sets invoice_status="CANCELLED". Does NOT commit.

  uncancel_invoice(db, invoice_type, invoice_id, acting_user) -> str
    Only CANCELLED can be uncancelled. Recomputes status from payment state. Does NOT commit.

  update_invoice_amount(db, invoice_type, invoice_id, new_amount, acting_user) -> None
    Updates amount column. DB trigger recalculates tax breakdown automatically. Does NOT commit.

  update_invoice_notes(db, invoice_type, invoice_id, notes, acting_user) -> None
    Sets or clears invoice notes. Does NOT commit.

  sync_invoice_status(db, invoice_type, invoice_id, acting_user) -> None
    Recomputes and writes invoice_status from payment state (mirrors DB trigger logic). Does NOT commit.

--- app/services/data_extractor.py ---
Purpose: Stateless functional extraction of structured contract data from PP-StructureV3 JSON output.

Key functions:
  extract_from_page1_one_time(page1_ocr: dict) -> TelkomContractData
    Primary extraction entry point. Parses PP-StructureV3 JSON structure.

  merge_with_page2(page1_data: TelkomContractData, page2_ocr: dict) -> TelkomContractData
    Adds: jangka_waktu (period_start, period_end), kontak_person_telkom (name, title, email, phone).
